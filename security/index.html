Critical K-1 — Twenty-one plaintext identities — 12 raw private keys and 9 BIP-39 mnemonics — shipped next to their addresses in the public mirror. The fleet has since RELAUNCHED on a fresh line; the exposed keys now hold only the retired line's ownership.

Found 2026-11-11 by round-4 re-audit (dex-sources first publication). Exposure window since 2026-11-11T10:35+03.

Eighteen Markdown raw-key rows in the mirror (across 17 files — 14 of them KEY-RECORD*.md, plus DEMO-AUTHORITY-KEY.md on two rows, RELAY-KEY.md and x402/server/WRITER-KEY.md), one shell runbook carried a key on an `export KEY=` line, and eight mnemonic rows carried a BIP-39 phrase. Across all of it: 21 distinct exposed identities — 12 raw private keys and 9 mnemonics, 9 of the mnemonic-derived addresses overlapping a key row. The mirror README excluded .env files; the key records are Markdown, so the exclusion did not catch them. The mirror holds a single commit, so the window opened with it.

Not a Solidity bug — a process failure. The NEW line is owned by a fresh, unexposed EOA and pays fees to a fresh, unexposed EOA, so the exposed keys can no longer move new-line fees or pause new-line contracts. What they DO still hold is the retired line: owner() of the old Base contracts, which are paused where a pause switch exists (read live). Subject to the same caveat as ever: principal is unreachable.

What is NOT at risk

  • Principal in vaults, escrows and forwarders — no owner path exists to it.
  • The FleetExecutor — stateless, no owner.
  • Token balances held by the contracts themselves.
  • NEW-line fees, recipients, pauses and roles — an exposed key cannot reach them.

Containment, in order

  1. DONE — fresh line deployed (CREATE2, chain-invariant) and its owner() accepted on every new Base contract; all new-line fees pay a fresh feeRecipient.
  2. DONE — the old Base line is frozen: p2 Registry, EscrowFactory and StreamFactory paused (receipts in the changelog). It can be abandoned in place; principal already in its vaults still vests out.
  3. DONE — the x402 writer moved to a fresh key; the exposed writer is revoked on the new facilitator.
  4. OPEN — the fees lane (FeeSplitter) was NOT redeployed and is still owned by an exposed key; its owner is non-transferable in bytecode, so closing it means a redeploy.
  5. DONE — the new keeper IS armed on the new factory (isKeeper[]==true, read live); the exposed keeper stays armed only on the paused old factory.
  6. DONE — secret scanning is armed BOTH ways: the gate runs unconditionally in the pre-push hook of the mirror stage (the stage is rebuilt each run, so the hook is re-installed and asserted before every commit; install failure now aborts the push instead of being swallowed) and in a CI workflow that also scans full history. It blocks a NEW unpinned key, a gitleaks hit, and a KEY-RECORD address that no longer derives from its keystore pointer. The 21 exposed identities (12 raw private keys + 9 mnemonics, overlapping) that already sit in the mirrored Markdown and shell runbooks are now pointers, not raw keys — the gate is what keeps the next one out, not what removes the old ones.
  7. Publish this note with the relaunch receipts; integrators find the leak regardless, the note is what keeps them.

Is the mirror public or private?

The mirror is PRIVATE (since 2026-11-11; it was public, and public is where the leak happened). It is NOT being re-published: the whole point of the flip is that a fresh clone no longer walks away with the keys, and a mirror that exists only to be read is worth less than the keys it carries. The other three repos (dex-products, dex-contracts, dex-fleet-mcp) are still public and carry no key files, so nothing public points at a private repo and no reader hits a 404. History rewriting does not un-leak anything either — only the relaunch does that — so the private window is bounded, not erased.
